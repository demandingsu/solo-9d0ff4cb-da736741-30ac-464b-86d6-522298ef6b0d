# 招标延期核对助手

采购代理人核对招标延期时，需要找回原公告与后续更正公告。本工具输入招标公告**列表页地址**，
沿同站点“下一页”自动抓取详情页，按字段标签读取项目编号、公告类型、发布时间、投标截止时间，
按**项目编号归并**、按**发布时间先后**处理，并在浏览器展示每个项目的当前结果与全部公告链接。

核对完成后，可从本次抓取结果中选取一条更正公告，把**项目编号、来源 URL 与正文可见文字**发布到
**公示镜像站**，供投标人查阅。镜像站按来源 URL 幂等保存，并处理“回执中断”等不确定结果。

## 处理规则

| 情形 | 处理结果 |
| --- | --- |
| 更正/延期公告**明确写出新的投标截止时间** | 用新时间**替换**旧时间，状态为“有效” |
| 较晚公告**声明延期却未给出新时间** | 状态标为 **“待核实”**，不再显示/沿用旧截止时间 |
| 所有公告均未公布截止时间 | 状态为“未公布” |
| 只有原始招标公告 | 沿用原截止时间，状态为“有效” |

同一项目的全部公告（原公告、更正、延期）按发布时间升序保留，并附原文链接，便于回溯核对。

## 发布到公示镜像站的规则

| 情形 | 处理结果 |
| --- | --- |
| 发送前查询：来源 URL 已有**相同内容** | 不重复发送，直接返回原镜像链接 |
| 发送前查询：来源 URL 已有**不同内容** | 判定**冲突**，展示已有镜像链接供人工核对 |
| 发送前查询失败 | 保持**待确认**，未发送 |
| 提交后**回执中断**（超时/断连/残缺响应） | 立即按来源 URL 复查；确认已刊登则显示已发布 |
| 回执中断且复查未发现记录 | 保持**待确认**，**不自动重发** |
| 回执中断且复查失败 | 保持**待确认**，**不自动重发** |
| 并发发布同一来源 URL | 镜像站唯一约束 + 写锁保证**只生成一条记录** |

结果页展示：发布状态、项目编号、原公告链接（经 `/view` 代理打开）、镜像链接、正文可见文字，
以及“发布前查询 → 提交 → 复查”的处理步骤。待确认时只提供“重新查询确认”（仅查询），不会盲目重发。

## 用 Docker Compose 启动

```bash
docker compose up --build
```

- 网页应用：<http://localhost:8000>
- 示例公告站（宿主机直连）：<http://localhost:8080>
- 公示镜像站（宿主机直连，含本地示例控制）：<http://localhost:8091>

在网页输入框中填入示例站点的列表页地址（容器内服务名地址，网页后端可直接抓取）：

```
http://example-site/list/page_1.html
```

点击“开始核对”后，页面展示：

1. 抓取概况：遍历的列表页（即“下一页”路径）、公告数、跳过链接、错误信息；
2. 各项目当前核对结果：项目编号、名称、状态徽章、**当前**投标截止时间；
3. 每个项目可展开的公告历史：公告类型、是否声明延期、发布时间、原截止时间及链接；
4. **发布更正公告到公示镜像站**：从本次抓取的更正/延期公告中选取一条，携带项目编号、
   来源 URL、正文可见文字提交。

### 离线演示“回执中断”

1. 在网页核对结果中勾选某条更正公告旁的 **“模拟回执中断”**，点击“发布”；
2. 镜像站会**先写入记录**，再向网页返回不完整响应并断开连接；
3. 网页把这次提交视为回执不确定，随即按来源 URL **复查**；
4. 复查确认记录已写入，结果页显示“已发布 / 回执曾中断”、镜像链接与原公告链接。

也可以直接打开镜像站 <http://localhost:8091>，点击“模拟下一次回执中断”，再从网页发起发布。
镜像站首页还提供“清空演示数据”，便于反复演示。上述控制默认启用；设置 `MIRROR_DEMO_MODE=0` 可关闭。

> 回执中断是刻意模拟的网络故障，镜像容器日志中出现一次连接未完成的错误属于预期现象。
> 公告链接默认指向容器内网地址（如 `http://example-site/...`），宿主机浏览器无法直接打开，
> 因此原公告链接统一经过网页后端的 `/view` 代理打开；镜像链接使用 `http://localhost:8091/...`。

## 镜像站接口

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/publications` | 发布；`201` 新建、`200` 已有相同内容、`409` 同 URL 内容冲突 |
| `GET /api/publications?source_url=...` | 按来源 URL 查询 |
| `POST /api/publications/query` | 查询并返回 `same_content`，供发布前查重/回执中断复查 |
| `GET /notice/{id}` | 公示页面（镜像链接） |
| `GET /` | 本地示例控制台 |

- `source_url` 会去掉首尾空白与 `#fragment`，协议/主机小写后作为唯一键；
- 内容指纹由“项目编号 + 正文”计算，正文统一换行并去掉行尾空白/首尾空行；
- `X-Simulate-Interrupt: 1` 请求头会让发布先落库再中断回执（网页的演示复选框即使用此机制）。

## 示例站点覆盖的场景

| 项目编号 | 场景 | 预期结果 |
| --- | --- | --- |
| CG-2026-001 | 更正公告写明新截止时间 | 有效，截止时间替换为 2026-11-06 10:00 |
| CG-2026-002 | 延期公告写明新截止时间 | 有效，截止时间替换为 2026-10-28 15:00 |
| CG-2026-003 | 延期公告声明延期但未给新时间 | **待核实**，旧时间不再显示 |
| CG-2026-004 | 两次更正：先改时间、后只声明延期 | **待核实**，第二次公告使前一时间失效 |
| CG-2026-005 | 仅原始招标公告 | 有效，沿用原截止时间 |
| CG-2026-006 | 公告未公布任何截止时间 | 未公布 |

## 解析器的字段适配

详情页解析不绑定固定模板，按“字段标签 → 值”依次尝试：

1. 表格行（`th/td`，含一行两对字段）；
2. `dl/dt/dd` 定义列表；
3. `label` + 输入控件（`input/textarea/select`）；
4. 正文中的“标签：值”段落。

标签支持常见别名（如“招标项目编号/项目编码”“投标文件递交截止时间/开标时间”等），
标签缺失时再用正则兜底；识别不到项目编号的页面会被跳过并记入“跳过链接”。

正文可见文字优先取 `article/main/#content/.content` 等正文容器，并排除脚本、样式、
隐藏元素与列表页面包屑；找不到正文容器时退回 `<body>` 全文。

## 安全与边界

- 仅跟随与入口**同站点**（协议+主机+端口一致）的“下一页”和详情链接，跨站链接跳过并记录；
- 只允许 `http(s)`，拒绝 `file://` 等协议；
- 上限：列表页 10 个、详情页 100 个、单请求超时 15 秒；
- `/view`、`/asset` 代理同样只转发 `http(s)` 目标；
- 发布结果页使用 POST/Redirect/GET，刷新页面只读，不会再次提交发布；
- 镜像站以 `UNIQUE(source_url)` + `BEGIN IMMEDIATE` 写锁保证并发下仍只有一条记录。
